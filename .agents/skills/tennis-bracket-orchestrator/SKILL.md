# Tennis Bracket Orchestrator

테니스 대진표 생성을 위한 4-에이전트 파이프라인 오케스트레이터. 입력 엑셀 템플릿 생성과 채워진 입력으로부터의 대진표 생성을 모두 처리.

## 실행 모드

**에이전트 팀 모드 (기본)**

`requirements-parser → bracket-composer ⇄ bracket-reviewer → excel-renderer` 파이프라인.
composer ⇄ reviewer 사이는 피드백 루프(최대 3회).

오버헤드를 피하기 위해 **단일 작업(예: 템플릿만 생성)일 때는 서브 에이전트로 단축 실행**한다.

## Phase 0: 컨텍스트 확인 (반드시 먼저 실행)

요청을 받으면 가장 먼저 작업 디렉토리에서 다음을 확인:

1. `_workspace/01_parsed.json` 존재 여부
2. `_workspace/02_bracket.json` 존재 여부
3. 사용자 요청이 (a) 신규 / (b) 부분 수정 / (c) 재실행 / (d) 템플릿만 생성 / (e) 입력 파일 받음 중 어느 것인지

판정 매트릭스:

| 사용자 요청 | _workspace 상태 | 실행 모드 |
|------------|----------------|-----------|
| "입력 양식 만들어줘" / "템플릿" | 무관 | **Phase A만** (excel-renderer 단독) |
| 채워진 입력 엑셀 경로 제공 | 무관 | **Phase B 전체** (4-에이전트 팀) |
| "다시 만들어", "재실행" | 02_bracket.json 있음 | 기존 → `_workspace_prev/`로 이동, **Phase B 전체** (새 시드) |
| "8번 게임만 바꿔" 등 부분 수정 | 02_bracket.json 있음 | **부분 재실행** (해당 슬롯만 composer 재호출) |
| "특정 사람 추가됐어" | 02_bracket.json 있음 | parser → composer만 재실행 |
| 처음 / `_workspace/` 없음 | 없음 | 사용자에게 입력 방식 확인 후 분기 |

## Phase A: 입력 템플릿 생성 (단축 워크플로우)

사용자가 "입력 양식만 줘"라고 하면:

1. `excel-renderer` 에이전트 1명만 호출 (서브 에이전트 모드)
2. 호출 시 `model: "opus"`, `subagent_type: "general-purpose"` 명시
3. 출력 경로 확인 (기본: `C:\Works\auto-tennis-bracket\테니스_입력양식.xlsx`)
4. `tennis-input-template/scripts/build_template.py` 실행. `--prefill image` 옵션 사용 시 첨부 이미지에서 추출 가능한 데이터 사전 채움.
5. 결과 파일 경로를 사용자에게 보고 + 작성 가이드 안내

작성 가이드 메시지 (사용자에게 보낼 것):
```
입력 템플릿이 생성됐어요. 시트 두 개를 채워서 다시 요청하세요.

📄 `참가자` 시트
  - 이름, 성별(남/여), 구력(년수, 정수), 구분(정회원/게스트)
  - IN시간, OUT시간 (HH:MM, 30분 단위)
  - 최소게임수/최대게임수 (선택) — 적으면 그 이상/이하로 배정

📄 `코트` 시트
  - 코트명, 시작시간, 종료시간 (HH:MM)
  - 기본값으로 A=1번, B=2번 (07:00~12:00), C=3번 (07:00~09:00) 채워져 있음 — 필요시 수정

채우신 후 "이 파일로 대진표 만들어줘" 라고 해주세요.
```

## Phase C: 주간 입력 초안 (카카오 캘린더 URL → 입력 엑셀)

매주 금요일 카카오 일정이 확정되면, URL만 받아 입력 엑셀 초안을 자동 생성한다.
사용자가 "이번 주 대진 초안", "카카오 일정 읽어줘" 또는 calendar.kakao.com URL을 주면 이 절차를 따른다.

1. **브라우저 연결**: gstack browse를 headed로 연결(connect-chrome 스킬 절차).
   카카오 로그인 세션은 `~/.gstack/chromium-profile`에 유지되므로 보통 재로그인 불필요.
2. **일정 읽기**: `browse goto <URL>` → `browse snapshot`.
   '로그인' 버튼만 보이면 세션 만료 — 로그인 버튼 클릭 후 사용자에게 창에서 직접 로그인 요청(비밀번호는 다루지 않음), 완료 후 재시도.
3. **초안 생성**: snapshot 텍스트를 파일로 저장 후
   `python .claude/skills/tennis-input-template/scripts/build_draft.py --snapshot <파일> --members 입력/클럽멤버_설정.xlsx`
   - 게스트 성별은 설명란에 없으므로 이름으로 추정해 `--guest-gender "이름=남|여"`로 전달(애매하면 사용자 확인)
   - 규칙: **등급 호칭 구력 환산 — 금배=20년, 은배=15년, 동배=10년**, 게스트 게임수 제약 기본 없음(`--guest-max` 명시 시에만 최대 적용), 이모지·공백 차이 무시(명수기❤️=명수기),
     명단에 없는 참석자는 초안 제외 + 경고(예: 탈퇴자), 기존 입력양식은 자동 백업
4. **검사·보고 후 종료**: `python 대진표_생성.py --check`로 초안을 검증하고 참가자 구성·부부·경고를
   요약 보고한 뒤 **여기서 끝낸다**. ⚠ **대진표 생성은 하지 않는다** — 사용자가 초안(IN/OUT·게스트 등)을
   직접 수정한 뒤 본인이 생성한다(`대진표_생성.bat` 또는 웹). 사용자가 명시적으로
   "대진표도 만들어줘"라고 할 때만 생성까지 진행.

## Phase B: 대진표 생성 (4-에이전트 팀)

채워진 입력 엑셀이 제공되면:

### Step 1: 팀 구성
```
TeamCreate (team_name: "bracket-team", members: [
  requirements-parser, bracket-composer, bracket-reviewer, excel-renderer
])
```

### Step 2: 작업 할당 (TaskCreate, 의존 관계 명시)
1. `T1: 입력 파싱` → owner: requirements-parser
2. `T2: 대진 생성` → owner: bracket-composer, blockedBy: [T1]
3. `T3: 품질 검토` → owner: bracket-reviewer, blockedBy: [T2]
4. `T4: 엑셀 출력` → owner: excel-renderer, blockedBy: [T3]

### Step 3: 데이터 흐름 (파일 기반)
모든 중간 산출물은 `C:\Works\auto-tennis-bracket\_workspace\` 하위에 저장:
- `01_parsed.json` (parser 출력)
- `02_bracket.json` (composer 출력, 재시도 시 덮어쓰기)
- `03_review.json` (reviewer 판정)
- 최종 엑셀은 작업 디렉토리에 `테니스_대진표_YYYYMMDD.xlsx` (YYYYMMDD는 사용자에게 확인 또는 입력 데이터의 날짜)

### Step 4: 재시도 루프
reviewer가 RETRY 판정 → composer가 retry_hint를 받고 시드를 변경하여 재실행 → 최대 3회.
3회 후에도 RETRY면 reviewer는 ACCEPT_WITH_WARNINGS로 전환하고 사용자에게 한계를 보고.

### Step 5: 사용자 보고
완료 시 다음을 메시지로 출력:
- 결과 엑셀 경로
- 참가자 게임수 요약 (max, min, 평균)
- 페어 중복 비율, 혼복 비율
- 경고 사항 (있다면)

## 데이터 전달 프로토콜
- **태스크 기반** (조율): TaskCreate/TaskUpdate로 진행 추적
- **파일 기반** (산출물): `_workspace/` 하위 JSON 파일
- **메시지 기반** (재시도): composer ⇄ reviewer SendMessage로 retry_hint 전달

## 에러 핸들링
| 에러 유형 | 처리 |
|----------|------|
| 입력 엑셀 파싱 실패 | parser가 즉시 사용자에게 어느 행/컬럼이 문제인지 보고 후 중단 |
| 가용 인원 < 4명인 슬롯 존재 | composer가 해당 슬롯 공석 처리, reviewer가 보고서에 명시 |
| reviewer 3회 RETRY 후에도 임계값 미달 | ACCEPT_WITH_WARNINGS로 진행, 보고서에 위반 항목 나열 |
| 엑셀 출력 실패 (파일 잠김 등) | excel-renderer가 사용자에게 파일 닫고 재실행 요청 |

## 코트별 배정 규칙

알고리즘이 따르는 코트 affinity (`schedule.py`의 `COURT_AFFINITY`):
- **A코트**: 여복 + 혼복 우선 (남복 페널티)
- **B코트**: 남복 우선 (여복/혼복 페널티)
- **C코트**: 무관 (모든 유형 균등)

여성 참가자는 07:30 이전 슬롯에는 가급적 배정하지 않음 (IN 시간이 7시 이전인 여성이 있다면 예외).

이 규칙은 score 가중치(`W["court_affinity"]`, `W["female_early_slot"]`)로 표현되며, 인원·코트 제약상 강제 불가능한 경우 자연스럽게 양보.

## 복식 종류 우선순위 (남복·여복 우선, 혼복은 차선)

- **단성 복식(남복/여복)이 원칙.** 만들 수 있으면 항상 먼저 배정한다.
- **단, 여자가 6명 이하면 혼복을 기본으로 1~2판 넣는다.**
  여복만 돌리면 늘 같은 사람끼리 붙게 되기 때문. `mixed_limits()`가 (최소 1판, 상한 2판)을 준다.
  최소 미달은 `mixed_below_min`으로 사실상 금지 — "혼복 0판"인 대진표는 안 나온다.
- **그 밖에 혼복이 늘어나는 경우** — 남복/여복을 더 짜봐야 **'쓸 만한 대진'이 안 나올 때**.
  쓸 만하다 = ① 같은 짝이 처음 ② 같은 4명이 다시 만나는 게 아님 ③ **두 팀 구력합 차이 ≤ 허용치** (전원 10년 미만 3 / 10년 이상 포함 4).
  (남자·여자 어느 한쪽이 4명 미만이면 애초에 단성 복식 불가 → 상한 무제한)
- **상한 계산.** `good_singles_capacity()`가 위 세 조건을 만족하는 단성 복식을 최대 몇 판
  만들 수 있는지 세고, 1인당 공평 게임수에 모자란 만큼 상한을 올린다.
  - 예: 방미라(3)+노남숙(3)=6 vs 서명숙(5)+정정희(5)=10 은 구력차 4 — 전원 10년 미만이라 탈락
  - 쓸 만한 조합이 넉넉하면 혼복은 기본 보장 1~2판만
  초과분은 `mixed_over_quota`로 급격히 비싸진다. 교류전도 같은 규칙(클럽 제약까지 반영).
- **이 완충이 없으면 "여자만 게임수가 1 적은" 대진표가 계속 나온다** —
  여복은 4명이 통째로 움직여서 그 그룹이 부족분을 매번 떠안기 때문.
  `gender_fairness`(전역)·`gender_catchup`(그리디)가 성별 평균 쏠림을 별도로 감시한다.
- 구현 게이트: `clean_singles_available()` — 남녀 양쪽 다 '페어도 매치업도 처음인' 단성 복식을
  아직 만들 수 있고, 허용량도 다 썼을 때만 혼복 페널티를 부과한다.
- 여복 후보가 아예 생성되지 않아 혼복만 나오는 것을 막기 위해,
  풀에 여자가 4명 이상이면 후보 상위권 밖이어도 여복 조합을 따로 확보한다.
- 다듬을 초안은 **점수 상위 + 복식 구성 다양성**으로 고른다. 로컬 개선은 경기 종류를 못 바꾸므로
  점수순으로만 자르면 구성이 다른 안(여복 3+혼복 2)이 다듬기 전 거친 점수로 탈락한다.
- **남자 게스트는 혼복보다 남복 위주** (`guest_in_mixed`, 소프트) — 혼복의 남자 자리는
  가급적 정회원이 맡는다. 여자 게스트는 혼복 가능(페널티 없음).
- **부부 페어** (멤버 설정 파일 `입력/클럽멤버_설정.xlsx` 또는 내장 기본값) —
  '피함' 부부는 혼복 같은 팀 회피(강한 소프트), '원함' 부부는 우대. 부부는 같이 오가므로
  **마지막 경기 종료를 30분 이내 차이**로 맞춘다(`couple_finish_gap`). 웹은 멤버 설정
  다운로드 버튼·업로드 칸 제공. review가 회피 실패·종료차 초과를 보고(RETRY 아님).
  - **예외: 신혁재·방미라**는 종료시각이 **반드시 정확히 30분 차이**(부부 시트 '종료시간차'
    =30분차이, `couple_finish_exact` 강한 소프트). 같이 끝나면 위반 — review가 미달성 보고.

## 개인별 최소·최대 게임수

- **최소게임수** (입력 양식 컬럼, 선택): 적으면 **적어도 그 게임수 이상 배정을 보장**(어기지 않는 규칙).
  - 보장 기준은 `min(최소게임수, 본인 가용 슬롯 수)` — IN~OUT이 짧으면 슬롯 수까지만.
  - 그리디 우대(`min_games_deficit`) + 위태로우면 강제 투입(`min_games_critical` — 3연속 금지를
    반영해 일찍 발동, 3연속 예외 없음. 보장 한도도 '3연속 없이 가능한 최대 게임수'로 자름)
    + 전역 `min_games_short=900*(부족)²`으로 지켜지고, review가 미달 시 RETRY 판정.
  - 여러 명의 최소게임수 합이 전체 자리를 넘으면 파싱 단계에서 경고.
- **최대게임수**: 그 수 이하로만 배정(hard). 최소 > 최대는 입력 에러.
- 두 값을 지정한 사람은 review의 그룹 게임수 격차 비교에서 제외(의도된 차이).

## 쉬는 텀 · 끝나는 시간

- **경기 사이 1시간 이상 공백을 최우선 회피** (`long_gap=200 × (초과 30분 단위)²`).
  기본 리듬은 "30분 쉬고 다음 경기". 2슬롯 연속은 정상, **3슬롯 연속은 금지(하드)** —
  2게임 연속했으면 반드시 한 번 쉰다. 3연속 없이 4명을 못 채우면 그 코트는 공석으로 둔다
  (인원이 적으면 이 규칙 때문에 매치 수가 줄거나 공백이 늘 수 있음 — 의도된 트레이드오프).
- **도착(IN) 후 첫 경기까지의 대기**도 같은 방식으로 억제(`long_start_delay`).
- **개인 총 유휴시간에 볼록(제곱) 페널티**(`idle_sq`) — 노는 시간이 한 사람에게 몰리지 않게 분산.
  총 유휴시간은 코트 사정상 거의 고정이므로, 이 항이 부담을 고르게 나누어
  결과적으로 **일찍 온 사람이 일찍 끝나고 늦게 온 사람이 뒤쪽 시간대를 맡는** 구조가 된다.
- 대기 기준점은 `eff_in` = `max(IN시간, 실제로 뛸 수 있는 가장 이른 슬롯)`, 여성은 07:30 이후.
- **구조적 한계를 반드시 함께 보고할 것:** 인원이 코트×4보다 훨씬 많으면
  (예: 21명 / 코트 2면 → 슬롯당 8명) 공백을 0으로 만들 수 없다.
  review의 `long_gaps` / `long_gap_players` / `total_idle_min`으로 실제 수치를 제시한다.

## 지난 대진표 페어 회피 (1주전/2주전)

새 대진표는 최근 대진표에서 **같은 팀이었던 페어**를 최대한 피한다.

- **입력:** 이전에 생성됐던 **결과 엑셀**(`테니스_대진표_YYYYMMDD.xlsx`)을 1주전/2주전 파일로 제공.
- **식별:** 참가자 id는 매주 새로 매겨지므로 페어는 **이름**으로 매칭한다(`history.py`가 결과 엑셀 그리드에서 같은 팀 이름쌍을 추출 — 손으로 고친 대진표도 실제 페어 반영).
- **우선순위:** 1주전(가중치 1.0) > 2주전(0.5). 두 주 연속 같은 페어면 가중치 합산.
- **적용 조건:** **우리 멤버끼리(단일 클럽)일 때만** 반영. 교류전(클럽 2개+)이면 자동 무시.
- **강도:** 소프트 페널티(`W["history_pair_repeat"]`, `schedule.py`). 코트 공석·3연속 금지 같은 하드 제약이 우선이라 인원이 적으면 일부 반복은 불가피.
- **없으면 미적용:** 이전 파일을 제공하지 않으면 이 기능은 꺼진 상태.

실행 경로:
- **CLI:** `python 대진표_생성.py --prev1 <지난주.xlsx> [--prev2 <2주전.xlsx>]`. 명시 안 하면 `--auto-prev`(출력/ 최근 2개 자동), `--prompt-prev`(대화형 확인), `--no-prev`(끔).
- **.bat 더블클릭:** 대화형에서 최근 대진표를 자동 추천 → 반영/직접선택/건너뛰기 확인.
- **웹:** "지난주 대진표"·"2주전 대진표" 파일 업로드 칸. 결과 화면에 "지난 대진표 대비 반복 페어 N쌍" 표시.
- **검증:** `review.py`가 겹친 페어를 low 이슈로 정보 표시(RETRY 사유 아님).

## 테스트 시나리오

**정상 흐름:**
- 입력: 첨부 이미지의 10명 참가자, 코트 A/B/C (A,B: 08-12, C: 07-09)
- 기대: 30분 단위 10개 슬롯, 코트별로 대진 배정, 참가자별 게임수 4~7회 범위
- 검증: 페어 중복 ≤ 5%, 연속 3슬롯 = 0, 혼복 비율 ≤ 20%, 1시간 이상 공백 인원 비율 ≤ 30%

**에러 흐름:**
- 입력: 참가자 3명만 있음
- 기대: parser가 "최소 4명 필요" 보고 + 진행 중단
- 검증: 결과 엑셀 미생성, 사용자에게 명확한 에러 메시지

## 후속 작업 지원

- **"다시" / "재실행" / "다른 패턴"**: `_workspace/`를 `_workspace_prev/`로 이동, 시드 변경 후 전체 재실행
- **"X번 게임만 수정해줘"**: composer만 호출, 해당 슬롯의 매치만 재계산 (인접 슬롯 영향 분석)
- **"참가자 추가/제거"**: parser부터 다시 실행
- **"코트 시간 변경"**: parser부터 다시 실행
- **"결과 양식 색깔/폰트 수정"**: excel-renderer만 호출

각 에이전트는 정의 파일의 "후속 작업" 섹션에 따라 동작한다.
